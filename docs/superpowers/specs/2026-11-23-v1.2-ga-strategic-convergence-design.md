## 1. 背景与意图 (Intent & Why)

在 Sprint 1 至 Sprint 3 周期中，`csilk` 已圆满交付了生产级 HTTP/3 (QUIC)、io_uring 固定缓冲区与 Direct FDs、物理 AF_XDP (XSK) 4 环内核旁路、Raft 联合一致性 (Joint Consensus)、io_uring 异步 WAL 批处理引擎、全异步非阻塞 PostgreSQL/MySQL 驱动以及本地 `llama.cpp` 原生推断等核心系统级基础设施。

作为 **v1.2 全景演进计划的最终收官里程碑 (Sprint 4: v1.2-GA)**，本设计的核心目标是将上述高性能底层基础设施全面向**应用层、生态扩展层与集群治理层**收敛闭环，完成三大战略子系统的工业级实现：
1. **OpenTelemetry 2.0 端到端全链路可观测性 (AI ↔ HTTP 统一 Trace)**；
2. **去中心化 Multi-Agent 任务协作网络 (Raft 联合拓扑与点对点租约工作窃取 Work-Stealing)**；
3. **WebAssembly (WAMR) 官方沙箱插件生态与指令级 Fuel 算力计量 SDK**。

通过本次交付，`csilk` 将确立作为兼具“硬件线速 I/O、原生嵌入式智能体、安全微沙箱与分布式去中心化协作”工业级 C23 智能 Web 框架的旗舰定位。

## 2. 目标、非目标与反目标 (Goals, Non-Goals & Anti-Goals)

### 2.1 目标 (Goals)
1. **Subsystem 1: OpenTelemetry 2.0 追踪闭环**:
   - 在 `csilk_ctx_t` 请求生命周期内，自动将大模型调用的 Prompt/Completion Tokens、首 Token 时延 (TTFT)、推理总耗时及 Tool Span 提取并无缝映射为标准 OTLP Span Attributes；
   - 维持 `csilk_otlp_span_t` 内存布局严格不变（通过侧车属性映射表 Sidecar Attribute Map 存储扩展属性），100% 保障 SOVERSION 1 ABI 兼容性；
   - 自动在入站 HTTP 请求、AI 调用链、异步中间件及下游客户端之间透传与传播 W3C `traceparent` 上下文；
   - 提供标准 OTLP JSON 导出与采样控制。
2. **Subsystem 2: 去中心化 Multi-Agent 任务网格**:
   - 将工作流 DAG 调度器 (`src/workflow/wf_graph.c`, `wf_run.c`, `wf_distributed.c`) 与 Raft 状态机（`raft_consensus.c`）深度打通；
   - 采用低时延的点对点（Peer-to-Peer）租约窃取模型：Raft 负责节点健康状态与集群拓扑仲裁，实际 DAG 任务切片通过 `csilk_mq` 进行双端队列（Deque）工作窃取，保证满足 P99 ≤ 5ms 的线速性能；
   - 统一使用 `const char* node_id` 作为拓扑节点句柄；在 Raft 节点发生动态增删（Joint Consensus）或 Leader 切换时，触发自动失效重平衡（Failover Rebalancing），确保任务执行无丢失、无重入。
3. **Subsystem 3: WebAssembly 官方 WAMR 沙箱插件生态与 Fuel 计量**:
   - 基于现有 CMake `FetchContent` 引入成熟的官方 **WAMR (WebAssembly Micro Runtime)** 核心，升级 `src/core/plugin/wasm_plugin.c`；
   - 通过 WAMR 官方 Fuel 接口 (`wasm_runtime_set_module_inst_fuel`) 落地指令级算力限制，防范死循环与拒绝服务攻击；
   - 通过 WAMR 原生 `NativeSymbol` 注册宿主调用导出表（Host-Calls：安全读取请求头、设置响应头、获取请求体切片、重写响应状态码）；
   - 提供独立可包含的开发者头文件 `include/csilk/plugin/wasm_sdk.h` 与 C/Rust 插件示例，未开启 `CSILK_ENABLE_WAMR` 时保持高保真模拟降级。

### 2.2 非目标 (Non-Goals)
- 编写完全从零自研的 WASM JIT 编译器（采用官方 WAMR 经典解释器与 AOT 机制，兼顾多平台极小体积）；
- 跨异构多集群/多地域级 Raft 跨广域网仲裁（以局域网/数据中心同集群分布式调度为基准）；
- 破坏项目原有的零外部硬依赖独立构建能力（WAMR 设为可配置编译选项 `CSILK_ENABLE_WAMR`，默认为可选支持）。

### 2.3 反目标 (Anti-Goals)
- **严禁破坏 SOVERSION 1 ABI 兼容性**：所有新增公开符号严格遵守 `csilk_*` 命名前缀，禁止修改既有公共结构体尺寸；
- **严禁在 cross-backend 代码中直接调用原生 `pthread_*` 或 `uv_*`**：统一通过 `csilk_thread_*`、`csilk_mutex_*` 及 `csilk_io_*` 抽象包装层；
- **严禁破坏声明置顶规范**：所有 `#include` 与全局/文件作用域 `static` 变量必须置于文件最顶部，函数体之前；
- **严禁造成性能退化**：核心路由与中间件流水线延迟退化严禁超过 1%，分布式窃取开销严禁拖垮吞吐。

## 3. 架构方案权衡 (Approaches Considered)

| 维度 | 方案一：分层解耦、递进交付（已采纳） | 方案二：全景一体化深度耦合（已放弃） | 方案三：轻量级最小可用原型（已放弃） |
| :--- | :--- | :--- | :--- |
| **实施策略** | 按照 OTel 2.0 → Multi-Agent 网格 → WAMR 沙箱 SDK 的顺序解耦推进 | 将 WAMR 作为分布式任务单元，OTel 强绑定入 Raft 状态机日志流中同时改动 | 仅做进程通信与字符串模拟，不实现真实 Fuel 与分布式调度 |
| **模块依赖** | 单向依赖，底座稳定后逐层构筑 | 网状双向依赖，容易出现循环包含与死锁 | 零依赖，但无实际功能 |
| **CI 验证风险** | 极低：每阶段拥有独立单元测试与 CI 门禁 | 极高：并发竞态与 TSAN 诊断极为复杂 | 无风险，但无法满足工业级 GA 要求 |
| **结论** | **推荐采纳**：符合项目一贯的工程规范与交付质量要求 | 放弃 | 放弃 |

## 4. 详细技术实现设计 (Detailed Technical Design)

### 4.1 子系统一：OpenTelemetry 2.0 追踪深度关联

#### 4.1.1 核心数据流与 ABI 保护
```
HTTP 入站请求 (包含或生成 traceparent)
  │
  ├──► otlp_trace 中间件解析并创建 HTTP Root Span (csilk_otlp_span_t)
  │      │
  │      ├──► 关联侧车属性表 (Sidecar Attribute Map, key=span_id)
  │      │
  │      ├──► 业务 Handler / AI 推断调度 (csilk_ai_chat / react_loop)
  │      │      │
  │      │      └──► 触发 csilk_ai_trace_t 记录 TTFT、Tokens、Tool Spans
  │      │
  │      └──► csilk_otlp_span_bind_ai_trace(root_span, ai_trace)
  │             │
  │             ├── Sidecar 注入 "gen_ai.usage.prompt_tokens"
  │             ├── Sidecar 注入 "gen_ai.usage.completion_tokens"
  │             ├── Sidecar 注入 "gen_ai.response.model"
  │             └── 创建 Tool Call 子 Spans (时间戳自 t_start 顺序偏移计算)
  │
  └──► HTTP 响应完成 ──► OTLP JSON 序列化器合并 Span + Sidecar ──► 批量异步导出
```

#### 4.1.2 关键接口规范 (`include/csilk/middleware/otlp_trace.h`)
```c
/**
 * @brief 将 AI 推理追踪上下文关联到当前 HTTP 请求的 OTLP Span。
 *
 * @param span 当前活动的 OTLP Span 句柄（其内部内存布局保持不变）。
 * @param trace 包含 Token 消耗与 Tool Spans 的 AI 追踪数据句柄。
 * @return 0 成功，-1 参数非法。
 */
int csilk_otlp_span_bind_ai_trace(csilk_otlp_span_t* span, const csilk_ai_trace_t* trace);

/**
 * @brief 在当前 Context 中自动提取并关联 AI 追踪。
 */
int csilk_otlp_ctx_attach_ai_trace(csilk_ctx_t* ctx, const csilk_ai_trace_t* trace);
```

### 4.2 子系统二：去中心化 Multi-Agent 任务协作网格

#### 4.2.1 核心架构与租约调度
```
              ┌──────────────────────────────────────────┐
              │           Raft Joint Consensus           │
              │   (集群拓扑视图 + 节点心跳存活 + 拓扑变更仲裁)  │
              └─────────────────────┬────────────────────┘
                                    │ 拓扑感知 (node_id 字符串标识)
              ┌─────────────────────▼────────────────────┐
              │       csilk_wf_cluster_grid_t            │
              │  (基于 csilk_mq 的分布式点对点 Work-Stealing) │
              └───────┬──────────────────────────┬───────┘
                      │                          │
        本地任务队列 (Local Deque)         远程对等窃取 (MQ Steal Request)
        push_bottom / pop_bottom          向拥有负载的活跃 Peer 请求任务切片
                      │                          │
              ┌───────▼──────┐           ┌───────▼──────┐
              │ Worker 1 执行│           │ Worker N 执行│
              └──────────────┘           └──────────────┘
```

#### 4.2.2 关键数据结构与调度规则 (`include/csilk/app/workflow.h` 与 `src/workflow/wf_distributed.c`)
- **调度单元与粒度**：任务切片为具备唯一 ID 的工作流 DAG 节点任务，各个节点通过预先注册的 Workflow 模板或 JSON DSL 协同执行；
- **点对点租约工作窃取**：本地队列空闲时，Worker 通过 `csilk_mq` 向负载较高的对等 Peer 发送窃取请求，获取带有效租约（Lease TTL）的任务切片，无需进行全局 Raft 仲裁，保持纳秒级响应；
- **故障重平衡 (Failover Rebalance)**：Raft 节点失联超时或触发剔除时，Leader 发布重平衡广播，失效节点未 ACK 的租约任务自动回归共享池；
- **接口扩展**：
  ```c
  /** @brief 初始化分布式 Agent 任务网格节点 */
  int csilk_wf_grid_init(csilk_wf_t* wf, csilk_raft_node_t* raft, csilk_mq_t* mq);
  
  /** @brief 触发工作窃取调度轮次 */
  int csilk_wf_grid_steal_and_execute(csilk_wf_t* wf);
  
  /** @brief 节点离线时自动重新分发遗留任务 */
  int csilk_wf_grid_rebalance(csilk_wf_t* wf, const char* failed_node_id);
  ```

### 4.3 子系统三：WebAssembly (WAMR) 官方沙箱插件生态与 Fuel 计量 SDK

#### 4.3.1 核心设计
1. **官方 WAMR 核心集成 (`CSILK_ENABLE_WAMR`)**：
   - 依赖项通过 CMake `FetchContent` 引入 WAMR (wasm-micro-runtime) 源码库；
   - 在 `src/core/plugin/wasm_vm.c` 中初始化 WAMR Runtime (`wasm_runtime_init`)，启用解释器模式与 WASI 支持；
   - 调用 `wasm_runtime_set_module_inst_fuel` 分配单次请求 Fuel 配额（默认 100,000 Fuel），耗尽时自动熔断并抛出 `CSILK_WASM_ERR_OUT_OF_FUEL`。
2. **宿主调用导出表 (NativeSymbol Host-Calls)**：
   - `host_get_header(uint32_t name_ptr, uint32_t out_buf_ptr, uint32_t cap)`: 校验线性内存边界后，安全拷贝请求头值至沙箱内部缓冲区；
   - `host_set_header(uint32_t name_ptr, uint32_t val_ptr)`: 设置请求/响应头；
   - `host_get_body(uint32_t out_buf_ptr, uint32_t cap)`: 安全拷贝请求体数据切片；
   - `host_set_status(int32_t code)`: 设置 HTTP 状态码并指示短路返回。
3. **开发者 SDK (`include/csilk/plugin/wasm_sdk.h`)**:
   - 纯 C 头文件，规范化 Guest 插件入口签名：
     ```c
     // Guest 插件入口约定
     int on_request(void);
     ```
   - 封装便利宏：`csilk_wasm_get_header()`、`csilk_wasm_set_header()`、`csilk_wasm_abort()`。

## 5. 质量保证与门禁规范 (Quality Assurance & Gates)

1. **单元测试与回归测试**:
   - `tests/middleware/test_otlp_ai.c`: 验证 HTTP Trace 自动吸纳 AI Token 与 Tool Span，侧车属性映射表读写正确；
   - `tests/workflow/test_wf_grid.c`: 验证 3 节点分布式 Work-Stealing 任务窃取与节点故障重平衡；
   - `tests/core/test_wasm_fuel.c`: 验证 Fuel 计量防死循环熔断、线性内存安全边界与 Host-Call 正确性。
2. **内存与并发安全**:
   - 通过全套 ASAN (AddressSanitizer + LeakSanitizer) 内存泄漏 0 检出；
   - 通过 TSAN (ThreadSanitizer) 验证分布式工作窃取无并发竞态。
3. **ABI 与版本规范**:
   - `./scripts/check_abi_compatibility.sh` 确保所有新公开 API 均属于 `csilk_*` 前缀；
   - `cmake --build build --target check-format` 0 差异通过。
