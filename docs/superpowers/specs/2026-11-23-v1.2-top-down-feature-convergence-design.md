# csilk 架构收敛设计规范：高层引擎闭环 (Top-Down Feature Convergence)

> **目标版本**: `v1.2.0-GA Convergence`  
> **设计日期**: 2026-11-23  
> **核心目标**: 将已落地的 OpenTelemetry 2.0 AI 追踪、去中心化 Multi-Agent 工作窃取网格、以及 WebAssembly (WAMR) 沙箱插件三大能力，无缝融合进主请求生命周期 (`csilk_app_t` / `csilk_ctx_t`) 与工作流调度引擎 (`csilk_wf_t`)，实现开箱即用的自动化框架级闭环。

---

## 1. 背景与演进动因 (Context & Motivation)

在 Sprint 4 (v1.2.0-GA) 期间，我们完成了三大战略组件的实现与单元测试验证：
- `csilk_otlp_span_bind_ai_trace` / `csilk_otlp_ctx_attach_ai_trace`
- `csilk_wf_grid_t` (双端工作窃取队列、按地址排序防死锁、租约仲裁与故障重平衡)
- `csilk_wasm_plugin_set_fuel` / `csilk_wasm_plugin_get_fuel` / `wasm_sdk.h`

虽然各组件单独运行良好（273 个单测 100% 通过，ABI 952 个纯净符号导出），但在实际业务应用时仍存在“孤岛效应”：
1. **工作流未接入网格**: `csilk_wf_t` 拥有 DAG 调度与状态机，但尚未持有 `csilk_wf_grid_t`，跨节点调度仍需应用手动调用切片接口；
2. **WASM 插件与应用层断层**: `csilk_app_t` 缺乏直接挂载 WASM 插件的 `csilk_app_use_wasm` 便捷接口，工作流节点的 WASM 执行未复用已加载实例与动态输入传递；
3. **AI 追踪需手动绑定**: 用户在 HTTP 路由中调用 `csilk_ai_chat` 时，需手动构造 `csilk_ai_trace_t` 并调用 `csilk_otlp_ctx_attach_ai_trace`，缺乏零样板代码的上下文感知自动埋点接口。

---

## 2. 方案比选与决策 (Approaches Considered & Decision)

### 备选方案 1：应用层包装器模式 (Application-level Wrapper)
- **实现方式**: 不改动核心结构，仅在应用示例中提供静态 helper 函数指导用户手动串联。
- **优点**: 核心库代码变动极少。
- **缺点**: 用户体验割裂，每个业务服务都需复制繁琐的样板代码，无法发挥框架级基础设施优势。

### 备选方案 2：侵入式合并 (Tight Coupling in Core Context)
- **实现方式**: 将 `csilk_wf_grid_t`、`csilk_wasm_plugin_t` 和 `csilk_ai_trace_t` 直接硬编码嵌入 `csilk_ctx_t` 和 `csilk_wf_s` 核心结构体中。
- **优点**: 调用路径最短。
- **缺点**: 严重破坏模块解耦边界（`include/csilk/core/context.h` 必须保持精炼稳定，破坏 SOVERSION 1 ABI 约束）。

### 备选方案 3：解耦式上下文注入与句柄挂接 (Decoupled Context Attachment & Handle Wiring) — **【推荐采纳】**
- **实现方式**:
  1. `csilk_wf_t` 结构体增加私有 `csilk_wf_grid_t* grid` 字段，暴露纯净公共 API `csilk_wf_set_grid` / `csilk_wf_get_grid` / `csilk_wf_submit_grid_task`；
  2. `csilk_app_t` 增加 `csilk_app_use_wasm` 接口，自动从插件提取中间件 thunk 注册至全局或分组中间件链；
  3. `csilk_ai_chat_ctx` / `csilk_ai_stream_ctx` 作为上下文感知高层函数，自动感知 `ctx` 中的 OTLP Trace 并静默上报指标。
- **决策理由**: 完美平衡框架自动化与模块正交解耦，100% 保持 SOVERSION 1 ABI 兼容。

## 3. 子系统详细设计

### 3.1 子系统一：Workflow ↔ Multi-Agent Task Grid 深度融合

#### 3.1.1 核心数据结构调整 (`src/workflow/workflow_internal.h`)
在 `struct csilk_wf_s` 中引入可选的网格指针：
```c
struct csilk_wf_s {
    char*                      name;
    csilk_wf_node_t**          nodes;
    size_t                     node_count;
    ...
    csilk_wf_grid_t*           grid;            /* 可选关联的去中心化任务协同网格 */
    ...
};
```

#### 3.1.2 导出接口定义 (`include/csilk/app/workflow.h`)
```c
/**
 * @brief 将分布式工作窃取网格挂接到工作流引擎。
 * @param wf 工作流句柄。
 * @param grid 工作窃取网格句柄（所有权仍由调用方或工作流生命周期管理）。
 * @return 0 成功，-1 失败。
 */
int csilk_wf_set_grid(csilk_wf_t* wf, csilk_wf_grid_t* grid);

/**
 * @brief 获取当前工作流挂接的工作网格句柄。
 */
csilk_wf_grid_t* csilk_wf_get_grid(const csilk_wf_t* wf);

/**
 * @brief 将工作流任务切片分发至工作流网格。
 *
 * 当本地队列负载饱和时自动推入本地 Deque，并向活跃 Peer 开放租约窃取。
 */
int csilk_wf_submit_grid_task(csilk_wf_t* wf, const char* task_id, const char* payload, size_t payload_len);

/**
 * @brief 尝试从当前工作流网格获取并执行就绪任务切片。
 */
int csilk_wf_poll_grid_task(csilk_wf_t* wf, char* out_task_id, size_t max_id_len);
```

### 3.2 子系统二：App ↔ WebAssembly (WAMR) 中间件与工具节点生态

#### 3.2.1 App 级 WASM 中间件挂载 (`include/csilk/app/app.h` 与 `src/app/app.c`)
```c
/**
 * @brief 将 WebAssembly 插件的导出函数直接注册为应用全局请求中间件。
 *
 * @param app 应用句柄。
 * @param plugin 已加载并初始化的 WASM 插件句柄。
 * @param func_name 插件导出的入口函数（如 "on_request"）。
 * @return 0 成功，-1 失败。
 */
int csilk_app_use_wasm(csilk_app_t* app, csilk_wasm_plugin_t* plugin, const char* func_name);
```
**实现机制**:
1. 调用 `csilk_wasm_plugin_middleware(plugin, func_name)` 获取分配的静态 thunk；
2. 调用 `csilk_app_use(app, thunk)` 将其装配入主请求中间件链；
3. 请求进入时，thunk 自动拦截请求并进入沙箱隔离执行，超额 Fuel 或 Trap 时短路响应。

#### 3.2.2 Workflow 级 WASM 插件节点增强 (`include/csilk/app/workflow.h` 与 `src/workflow/wf_tools.c`)
重构 `csilk_wf_add_wasm_plugin_node`：
- 支持传入预加载的 `csilk_wasm_plugin_t*` 实例，消除每次节点执行时重复读取文件与解析字节码的高额损耗；
- 前置节点输出的 `csilk_data_t`（如 JSON 载荷）直接作为 `json_input` 传给沙箱环境，执行结果打包为下一节点的标准输出。

### 3.3 子系统三：HTTP ↔ OpenTelemetry 2.0 AI 追踪全自动埋点

#### 3.3.1 上下文感知 AI 推理 API (`include/csilk/drivers/ai.h` 与 `src/drivers/ai/ai.c`)
```c
/**
 * @brief 请求上下文感知的 AI 对话接口，自动生成并绑定 OpenTelemetry W3C Span。
 *
 * @param driver AI 驱动实例（OpenAI / Ollama / DeepSeek / 本地模型）。
 * @param ctx 当前请求上下文（若非 NULL，自动从中提取 traceparent 并在侧车表中注入 GenAI 规范指标）。
 * @param prompt 输入提示词。
 * @param out_buf 响应接收缓冲区。
 * @param out_len 缓冲区容量。
 * @return 0 成功，负数表示错误。
 */
int csilk_ai_chat_ctx(csilk_ai_driver_t* driver,
                      csilk_ctx_t*        ctx,
                      const char*         prompt,
                      char*               out_buf,
                      size_t              out_len);

/**
 * @brief 请求上下文感知的 AI 流式推理接口，自动记录 TTFT（首 Token 延迟）与总延迟。
 */
int csilk_ai_stream_ctx(csilk_ai_driver_t* driver,
                        csilk_ctx_t*        ctx,
                        const char*         prompt,
                        csilk_ai_stream_cb_t cb,
                        void*               user_data);
```
**实现机制**:
1. 记录高精度时间戳 `t0 = csilk_time_now_ns()`；
2. 调用底层驱动完成推断通信；
3. 计算 `latency_ms = (csilk_time_now_ns() - t0) / 1000000`；
4. 自动构造局部 `csilk_ai_trace_t`，填入 `latency_ms`、`prompt_tokens`、`completion_tokens`、`model`；
5. 若 `ctx` 有效，自动执行 `csilk_otlp_ctx_attach_ai_trace(ctx, &trace)`，无缝融入当前 HTTP 请求追踪链路。

## 4. 质量门禁与兼容性保障

1. **SOVERSION 1 ABI 约束**:
   - 新增函数统一采用 `csilk_*` 前缀；
   - 保持公共结构体不改变内存布局，内部字段（如 `grid`）仅置于 `workflow_internal.h` 的内部非导出结构体中；
   - 运行 `./scripts/check_abi_compatibility.sh` 确保 100% 纯净。
2. **测试驱动设计 (TDD)**:
   - `tests/workflow/test_wf_grid_integration.c`: 验证 `csilk_wf_set_grid` 与工作流任务分发/拉取；
   - `tests/app/test_app_wasm.c`: 验证 `csilk_app_use_wasm` 中间件拦截；
   - `tests/drivers/ai/test_ai_ctx_trace.c`: 验证 `csilk_ai_chat_ctx` 自动向 `csilk_ctx_t` 注入 OTLP 侧车属性。
3. **格式与规范**:
   - 保证 LLVM 18 clang-format 0 差异。
