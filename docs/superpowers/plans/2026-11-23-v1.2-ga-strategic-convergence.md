# csilk Sprint 4 (v1.2-GA) 战略功能收敛实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 csilk v1.2-GA 最终里程碑收尾，交付 OpenTelemetry 2.0 端到端追踪链路、基于 Raft 与 MQ 的去中心化 Multi-Agent 任务工作窃取网格、以及集成官方 WAMR 的 WebAssembly 沙箱插件引擎与 Fuel 计量 SDK。

**Architecture:** 采用分层解耦的递进式实施方案：首先在不破坏 SOVERSION 1 ABI 的前提下通过侧车属性表打通 AI 与 HTTP W3C 追踪；随后利用现有 Raft 拓扑和 MQ 协议落地纳秒级无阻塞点对点工作窃取双端队列；最后在插件层接入官方 WAMR 运行时并导出安全宿主调用与 Guest SDK。

**Tech Stack:** C23 (`CMAKE_C_STANDARD 23`), W3C Trace Context (OpenTelemetry OTLP JSON), Raft Joint Consensus, Linux io_uring / MQ, WAMR (wasm-micro-runtime 2.4.4), CMake, LLVM 18 clang-format.

## Global Constraints

- C23 语言标准：内置 `nullptr`、`bool` 与 `static constexpr`，禁止引入 `<stdbool.h>`。
- 声明置顶规范：所有 `#include` 与文件作用域 `static` 变量必须严格置于文件最顶部，首个函数定义之前。
- ABI 稳定性约束：绝不修改已导出公共结构体（如 `csilk_otlp_span_t`）的尺寸与偏移；所有新公开函数严格使用 `csilk_*` 前缀；维持 SOVERSION 1 兼容性。
- 零裸系统调用：严禁在 `src/core/`、`src/workflow/` 或跨后端模块直接调用未封装的 `pthread_*` 或 `uv_*`，必须使用 `csilk_thread_*`、`csilk_mutex_*`、`csilk_io_*`。
- 构建独立性：WAMR 特性通过可选配置 `CSILK_ENABLE_WAMR` 隔离，默认在未开启或无网络时无缝回落至内置高保真桩模式。
- 代码风格门禁：全量文件必须严格符合 LLVM 18 `clang-format` 规范，`check-format` 必须 0 差异通过。

## Review Focus

1. **SOVERSION 1 ABI 破坏风险**: 若直接在 `csilk_otlp_span_t` 结构体中添加属性字段，会导致旧版外部二进制动态链接时内存越界。*测试保障：Task 1 中运行 `./scripts/check_abi_compatibility.sh` 确保符号与结构体尺寸 0 破坏。*
2. **Work-Stealing 跨线程/跨节点数据竞争**: 在多节点并发发起窃取请求时，双端队列的 Top/Bottom 指针可能产生 ABA 或重复弹出。*测试保障：Task 2 中编写并发窃取测试并在 TSAN (ThreadSanitizer) 下运行 0 数据竞争。*
3. **Raft 拓扑切换时的任务丢失**: 节点离线触发故障重平衡时，未 ACK 租约的任务切片可能被两方节点同时执行或彻底丢失。*测试保障：Task 2 中测试节点断网模拟，验证租约超时回归与任务幂等重试。*
4. **WASM 线性内存跨界破坏与逃逸**: 恶意 Guest 插件通过传入越界指针试图读取宿主核心内存。*测试保障：Task 3 中测试在 Host-Calls 中强校验 `ptr + cap <= linear_mem_size`，越界时立即熔断报错。*
5. **Fuel 耗尽死循环保护失效**: 递归或死循环的 WebAssembly 字节码未能被及时中断导致 Worker 线程挂死。*测试保障：Task 3 中测试 100,000 Fuel 限制下，`while(1)` 字节码在 1ms 内安全抛出 `CSILK_WASM_ERR_OUT_OF_FUEL`。*
